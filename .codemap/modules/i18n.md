# Module: Internationalization (i18n)

> 多语言国际化支持。通过 Chrome Extension `_locales/` 目录提供 8 种语言的翻译文件，JS 层通过 `chrome.i18n.getMessage()` 和自定义 `i18n.js` 工具函数获取翻译字符串。

## 1. Scope & Purpose

为扩展所有界面提供多语言支持。覆盖范围：
- manifest.json 中的 `name`/`description`/`commands.*.description` (`__MSG_*` 占位符)
- JS 中所有 UI 字符串（通过 `chrome.i18n.getMessage()`）
- HTML 中通过 `__MSG_*` 占位符直接替换的文本
- catch-script 中页面级 UI 面板文本（通过 `catch-script/i18n.js`）

支持语言：英文(en)、中文简体(zh_CN)、中文繁体(zh_TW)、日文(ja)、西班牙文(es)、葡萄牙文(pt_BR)、土耳其文(tr)、越南文(vi)

## 2. Folder Architecture

```
_locales/
├── en/messages.json      ← 英文（默认语言，fallback）
├── zh_CN/messages.json   ← 简体中文
├── zh_TW/messages.json   ← 繁体中文
├── ja/messages.json      ← 日文
├── es/messages.json      ← 西班牙文
├── pt_BR/messages.json   ← 葡萄牙文（巴西）
├── tr/messages.json      ← 土耳其文
└── vi/messages.json      ← 越南文
```

## 3. Always-load vs On-demand

### Always-load (read these first for any task in this module)

- `_locales/en/messages.json` — 默认语言，所有其他语言的翻译基准
- `js/i18n.js` — JS 层国际化工具函数

### On-demand (read only when the task touches these areas)

- `catch-script/i18n.js` → 当修改页面内嵌面板的翻译时
- `_locales/{lang}/messages.json` → 当修改特定语言的翻译时

## 4. Rules & Boundaries

- `default_locale` 设为 `en`（manifest.json），任何未翻译的 key 回退到英文
- messages.json 格式严格遵循 Chrome i18n API：`{ "key": { "message": "...", "description": "..." } }`
- 添加新翻译 key 时必须同步更新所有 8 个语言文件
- `tools/sync-locales.js` 可自动化同步新增 key 到所有语言（标记为 TODO 待翻译）
- 占位符语法：`$KEY$`（非 `{key}`）

## 5. Source of Truth

| Concept | Canonical file | Notes |
|---------|---------------|-------|
| 默认翻译 | `_locales/en/messages.json` | 基准语言，最高优先级 |
| JS i18n 工具 | `js/i18n.js` | 封装 `chrome.i18n.getMessage()` |
| 页面 i18n | `catch-script/i18n.js` | 页面上下文无法直接调用 Chrome API |
| 同步工具 | `tools/sync-locales.js` | 自动化翻译 key 同步 |
